# SockLock Variants (MVP)

Утиліта для motion-дизайнерів SockLock. Із брифу та скрипту перевіреного креативу готує **4–12 нових відкриттів** для модифікацій:

- **хук** — перша фраза озвучки;
- **текст на екрані**;
- **ідея першого кадру** та пояснення зміни.

Варіанти проходять детерміновані перевірки, редагуються дизайнером і експортуються лише після ручного затвердження. Основний скрипт і пропозиція залишаються незмінними.

## Яку проблему розвʼязує

> «Половину дня я переписую одне й те саме: беру скрипт переможця і вручну придумую нові хуки, перші фрази, варіанти тексту на екрані». — motion-дизайнер

- Одна модифікація займає приблизно 3 години; команда виробляє близько 240 модифікацій на місяць.
- 240 модифікацій і 40 оригіналів потребують приблизно 1 200 дизайнерських годин за даними кейсу. Це привід уточнити місткість команди, не доказ понаднормової роботи.
- Для цільового spend $800 000 потрібно близько 500 модифікацій; джерело модифікацій приносить $92 000, або 65,7% EGP.

Утиліта скорочує повторювану підготовку відкриття, але не замінює дизайнера, монтаж або рішення UA. Частка підготовки у 3 годинах і реальна економія часу — припущення для пілоту, а не досягнутий результат.

## Швидкий старт

Потрібен **Node.js 22 або новіший**; перевірено на Node.js 24.16.0. У папці проєкту:

```bash
npm ci
npm start
```

Відкрийте http://127.0.0.1:4317. Якщо порт зайнятий, сервер надрукує інший із наступних дев’яти. У PowerShell за обмеження запуску `npm.ps1` використовуйте `npm.cmd`.

**Варіант 1. Microsoft Foundry / Azure OpenAI — типовий провайдер.** Створіть локальний файл конфігурації з [шаблону](.env.example), лише якщо його ще немає:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Заповніть `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_DEPLOYMENT` і `AZURE_OPENAI_API_KEY`, потім перезапустіть сервер. Endpoint має закінчуватися на `/openai/v1/`, **без `/responses` або `/chat/completions`**. Використовується ім’я deployment, не ім’я моделі з каталогу. Ключ вводьте самостійно в локальному редакторі, не в чаті й не в GitHub.

**Варіант 2. Anthropic API.** Заповніть `ANTHROPIC_API_KEY`, за потреби `ANTHROPIC_MODEL`, і виберіть **Claude API** у списку Provider. Підписка Claude Code не є API-ключем цього адаптера; інтеграції з CLI Claude Code тут немає.

**Без ключа.** Виберіть **Local templates**, натисніть **Insert example**, потім **Generate variants**. Це детерміновані шаблони з введеного брифу, не LLM і не збережена відповідь, прихована під AI-режимом. Після встановлення залежностей мережа для нього не потрібна.

**Тести й браузерна перевірка:**

```bash
npm test
npx playwright install chromium
npm run verify
```

Перевірено 44 unit/integration-тести та 18 браузерних сценаріїв. Тести використовують локальні дані й підставні відповіді; платні API-запити не виконуються. Окремого генераційного CLI на кшталт `npm run cli` немає.

## Як працює дизайнер

1. Натискає **Insert example** або вводить свій бренд, аудиторію, біль, **Source script**, **Unchanged offer** і **Verified facts**. Кожен факт — із нового рядка; демобриф явно синтетичний.
2. Вказує кількість 4–12, вибирає кути в **Creative angles**, за потреби відмічає до п’яти скриптів у **Reference library** та вибирає Provider.
3. Натискає **Generate variants**. У Foundry/Claude бриф і вибрані референси надсилаються зовнішньому провайдеру; запит має власну вартість і ліміти.
4. Перевіряє картки зі статусами **Unreviewed** або **Blocked**. Відсутність блокування не гарантує правильні факти чи комплаєнс.
5. Олівцем редагує текст, кадр і кут. **Save and recheck** повторює перевірки й скидає схвалення картки. **Approve draft** вручну позначає придатну чернетку.
6. **Export approved** завантажує лише схвалені чернетки у CSV/JSON. Сервер перед експортом перевіряє їх знову. Вкладки All / Unreviewed / Approved лише фільтрують показ.
7. Дискетою зберігає workspace, папкою імпортує його. Після імпорту всі схвалення скидаються. Зміна брифу, кутів або вибраного референса вимагає нової генерації.

Варіанти мають ID `V01`, `V02`; metadata містить run ID, провайдер, модель, час і usage. Автоматичні назви реклам на кшталт `W07_AI_question_01`, публікація в Meta та синхронізація з Airtable не реалізовані.

### Чому зроблено саме так

- **Провайдер окремо від логіки.** Контракт запису — `id`, `label`, `source`, `status()` та `generate()`. Новий адаптер додається в реєстр без змін генератора, HTTP API чи HTML; для тестів доступне `additionalProviders`.
- **Кути подачі.** Дозволені тільки вибрані ID; ліміт на кут — `ceil(count / selectedAngles)`. Для 10 варіантів і 9 кутів — максимум 2, для 10 і 2 — максимум 5. Це контроль різноманітності, не прогноз роботи Meta.
- **Приклади відокремлено від фактів.** Референси передають тон і структуру, але не додають дозволених цін, гарантій чи властивостей продукту. Синтетичні приклади не називаються реальними переможцями.
- **JSON-схема плюс локальні перевірки.** Foundry отримує сумісну strict schema; повні обмеження довжини й кількості перевіряються локально. Для моделі без підтримки strict schema можна явно вибрати `json_object`.
- **Людина затверджує.** Перевірки — евристики, тому жодна AI-відповідь не схвалюється автоматично. Редагування скидає approval, експорт повторно перевіряється сервером.
- **Контроль витрат.** Таймаут SDK 45 секунд, автоматичні повтори вимкнені. Refusal, обрізання або неправильний JSON дають явну помилку, не перехід на шаблони чи іншу платну модель.
- **Локальний захист.** Сервер слухає `127.0.0.1`, перевіряє Host/Origin, обмежує JSON до 64 KB, генерацію — до одного активного запиту та 20/хв. Ключі лише на сервері; текст вставляється через `textContent`, CSV захищається від формул Excel.

| Провайдер, endpoint, deployment, авторизація | Локальна конфігурація за [шаблоном](.env.example) |

У бібліотеці: до 20 скриптів по 30–4000 символів, JSON до 50 KB. В AI-запиті: максимум 5 референсів, разом до 8000 символів. Око відкриває перегляд, олівець — редагування, кошик — видалення; чекбокс додає скрипт у наступний промпт.

Додана бібліотека зберігається в **localStorage цього браузера й адреси**, не в серверній базі. Для іншого браузера чи комп’ютера експортуйте її у JSON. Workspace містить тільки вибрані референси та кути; імпорт відновлює їх і скидає approvals. Очищення брифу не видаляє бібліотеку.

## Доступ до моделей

| Спосіб | Для чого | Як увімкнути |
|---|---|---|
| Microsoft Foundry / Azure OpenAI | AI-генерація через Azure; типовий провайдер | `AI_PROVIDER=foundry`, endpoint, deployment, `AZURE_OPENAI_AUTH=key`, локальний ключ |
| Microsoft Entra ID | Foundry без API-ключа за наявності Azure-ідентичності | `AZURE_OPENAI_AUTH=entra`; `DefaultAzureCredential`, scope `https://ai.azure.com/.default` і роль `Cognitive Services OpenAI User` |
| Anthropic API | Альтернативна AI-генерація | `ANTHROPIC_API_KEY`, за потреби `ANTHROPIC_MODEL`; вибрати Claude API |
| Local templates | Офлайн-заготовки й тестування процесу | Вибрати Local templates; без LLM, ключа та API-списань |

Підписка ChatGPT/Claude Code не підставляється замість API-ключа. Foundry використовує офіційний `openai` SDK і v1 Chat Completions; Anthropic — офіційний SDK та структуровану tool-відповідь. Позначка **Configured** означає заповнену конфігурацію, не перевірку валідності ключа або RBAC.

Модель Foundry задається deployment у локальній конфігурації. Немає автоматичного перемикання key ↔ Entra або retry `json_schema` ↔ `json_object`. Не вводьте секрети, персональні дані чи конфіденційні скрипти без дозволу: бриф і вибрані референси надсилаються AI-провайдеру.

Офіційний контракт: [Microsoft Learn — Structured outputs](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/structured-outputs).

## Вартість

Ціна Foundry залежить від моделі, версії й deployment type. Metadata зберігає usage, але **вартість Azure автоматично не обчислюється**. Перед live-тестами погодьте бюджет і звірте [тарифи Azure OpenAI](https://azure.microsoft.com/en-us/pricing/details/cognitive-services/openai-service/).

Порівняльний приклад для **Anthropic Haiku 4.5**, не тариф Azure: 250 запусків ×8 000 input +250 ×2 000 output =2 млн input та 0,5 млн output. За ставками $1/$5 за млн це $4,50; резерв повторних ручних спроб — $10/місяць. Це припущений обсяг, не замір live AI. Local templates не має API-витрат.

Стабілізація й підготовка пілоту оцінені у 22–30 командних годин; за умовної ставки $40/год — $880–1 200 одноразово. З резервом $10 і 1–2 годинами підтримки — $50–90/місяць у цьому порівняльному кошторисі. Річний TCO $1 480–2 280 не обов’язково нижчий за готові чати.

**Build vs buy:** [Claude Pro](https://claude.com/pricing) і [ChatGPT Plus](https://chatgpt.com/pricing) — $20/користувач/місяць; [Jasper Pro](https://www.jasper.ai/pricing) — $69/місяць або $59 з річною оплатою. Перевірено 08.11.2026; ліміти, податки й корпоративні вимоги враховуються окремо. Наш шар виправданий лише за ≥20% економії часу проти звичайного AI-чату при не гіршій якості.

## Як поміряти успіх

**Пілот:** 2 дизайнери, 2 тижні; по 12 зіставних задач кожному: 4 вручну, 4 у звичайному AI-чаті, 4 в утиліті. Чергуємо порядок і складність референсів. Міряємо час **до 3 придатних відкриттів**, включно з брифом, читанням, перегенераціями, правками та експортом.

| Метрика | Зараз | Ціль | Коли |
|---|---|---|---|
| Час підготовки 3 придатних відкриттів | Потрібен baseline | −50% проти ручної роботи, −20% проти чату в обох дизайнерів | На двотижневому пілоті |
| Придатність чернеток після малих правок | Потрібен baseline | ≥70%, не гірше контрольного чату | На пілоті |
| Добровільне повернення | Не виміряно | 2/2 користуються ≥4 днів на тиждень | На пілоті |
| Критичні непідтверджені claims у схваленому експорті | Не виміряно | 0 за ручною перевіркою | Кожна задача |
| Повний час готової модифікації | ~3 години з кейсу | Базова гіпотеза ≤1,8 години | Після перевірки текстового процесу |
| ROMI додаткового рекламного бюджету | Не виміряно | ≥125% за однаковою методикою | Окремий тест UA, 4–6 тижнів |

**Звідки дані:** щоденник задач і часу з anonymous designer ID; оцінювання якості без назви методу; для реклами — погоджений UA/аналітиком одночасний контроль, однакові offer, ринок, budgets і вікна атрибуції. Назву методу/run ID додаємо до обліку задач; інтеграції з кабінетом немає.

**Стоп:** утиліта не випереджає чат, переносить роботу на reviewer, погіршує якість або потребує примусового adoption. Не масштабуємо рекламу нижче ROMI 125%. Black Friday і Q5 спотворюють «до/після»; 24 текстові задачі не доводять рекламну окупність.

За формулою кейсу `EGP = Spend × (ROMI − 100%)` базовий сценарій — **+$27 600 EGP/місяць**, але лише за t=1,8 години, 720 доступних годин, реалізації 60% потенціалу й додаткового ROMI=130%. За 480 годин — близько $4 485; без додаткового spend — $0. Це гіпотези, не чистий прибуток і не досягнутий ефект. Розрахунок: [CSV](deliverables/economics.csv), [JSON](deliverables/economics.json), `npm run calculate`.

## Обмеження MVP

- Евристики claims, чисел і схожості можуть пропускати помилки або давати false positives; `Approved draft` — рішення людини, не сертифікація чи дозвіл Meta.
- Схожість — Jaccard наборів слів, поріг 0,72, не семантична модель; окремої перевірки проти першого VO вихідного скрипту ще немає.
- JSON-схема не гарантує якість; `json_object` гарантує формат, локальна перевірка контролює поля, довжину, кількість і кути.
- Референси впливають на промпт без fine-tuning. Local templates їх не аналізує й не є доказом якості AI.
- Пояснення англійською. Немає Claude Code subscription-адаптера, генераційного CLI, Markdown-експорту, публікації чи генерації відео.
- Бібліотека локальна для browser/origin; очищення даних сайту може її видалити. Конфіденційні референси не публікуйте.
- Технічні тести й відео не доводять adoption чи EGP. Авторські перевірки Foundry/Claude виконувалися зі stub/mock-відповідями; бізнесовий пілот не проводився.
- Сервер для localhost. Мережевий production потребує authentication, roles, retention та security review.
